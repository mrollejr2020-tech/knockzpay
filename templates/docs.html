Authentication

KnockzPay supports two authentication methods: API Key (simple) and Ed25519 asymmetric signing (hardened production).

API Key (Vault-Locked)

KnockzPay uses **Vault-Locked** security. When you generate a key, we hash it instantly. We only store a hidden fingerprint, never the plain key. This provides **Key Immunity** — even if our database leaks, your secret keys stay safe (**Leak-Proof Security**).

curl -X POST https://api.knockzpay.com/v1/payments \
  -H "X-API-Key: kz_live_your_key" \
  -H "Content-Type: application/json"

Ed25519 Asymmetric (Production)

For high-volume production use. Sign requests with your Ed25519 private key. KnockzPay verifies with your registered public key. Includes replay protection via Redis-backed nonce tracking.

# Required headers for asymmetric auth:
X-Knockz-Merchant-Id: 12345
X-Knockz-Signature:   <base64-ed25519-sig>
X-Knockz-Timestamp:   1714900000
X-Knockz-Nonce:       <unique-uuid>
X-Knockz-Key-ID:      v1

Webhooks

Real-time event delivery with automatic retry and Ed25519 payload signing.

Register a Webhook

POST /v1/webhooks
{
  "url":    "https://yourapp.com/webhooks/kp",
  "events": ["payment.settled", "anomaly.detected"]
}

Event Types

Event Description
payment.settled Payment finalized and immutable
payment.failed Payment could not complete
stream.stopped Streaming session ended (cap or manual)
anomaly.detected Suspicious activity → auto-freeze triggered

Idempotency

All mutation endpoints require an idempotency_key. Retry the same request safely — KnockzPay will return the original response without double-charging.

// Generate per-request
const key = `charge_${userId}_${Date.now()}`;

const txn = await kp.charge({
  amount:          0.01,
  recipient_id:    userId,
  idempotency_key: key   // safe to retry
});

Errors

Status Code Meaning
